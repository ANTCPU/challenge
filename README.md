# ANTCPU Challenge Repo

**github.com/ANTCPU/challenge**

This is the home base for dev-track challengers in the 
[antcpu Human in the Loop Internship Challenge](https://antcpu.io).

---

## What This Is

A two-phase developer experience that grows with every cohort.

Phase 1 is simple by design. Phase 2 raises the stakes.
The challengers who run through this program are the ones 
who will shape what it becomes.

---

## Phase 1 — Clean Repo · Show Us What You Can Do

**Weeks 1 & 2**

This repo is your starting point. No existing code to inherit.
No legacy to untangle. Just you, a blank slate, and a real brief.

The goal is simple: **show us how you think and how you build.**

- Set up your environment
- Document your approach before you write a line
- Build something small, clean, and intentional
- Submit it as a PR to this repo

There are no trick questions here. We want to see:
- How you structure a project from scratch
- How you communicate your decisions
- How you use AI as a co-pilot, not a crutch
- Whether your code does what you say it does

Week 1 is exploration. Week 2 is execution.
By the end of Week 2 your PR is your proof.

---

## Phase 2 — Fork from Ads · Work on a Real Enhancement

**Weeks 3 & 4**

Phase 2 is where it gets real.

The [ANTCPU/ads](https://github.com/ANTCPU/ads) repo is the 
live codebase behind [antcpu.cloud](https://antcpu.cloud) — 
a production ad network with real users, real traffic, and 
real open problems.

**Your Phase 2 task:** fork from `ANTCPU/ads`,Get a real task and submit a real enhancement PR.

Before you touch any code, read:
- [`DEV.md`](https://github.com/ANTCPU/ads/blob/main/DEV.md) 
  — full stack reference, key files, database schema, agent 
  system, known gaps
- [`CONTRIBUTING.md`](https://github.com/ANTCPU/ads/blob/main/CONTRIBUTING.md)
  — how to work in this codebase

The known gaps in DEV.md are your targets. They are real 
problems, documented with file locations and priority levels. 
A clean fix with clear reasoning is worth more than an 
ambitious PR that doesn't run.

**The build rule here is the same as the rest of the codebase:**
> Observe → Document → Discuss → Build.
> Code follows the document. Never the other way around.

---

## How This Grows

Every cohort that runs through this challenge makes it better.

The tasks will get more detailed. The briefs will get sharper.
The fork targets will get more specific. That happens because 
challengers like you run through it, hit the edges, and show 
us what needs to change.

Phase 1 stays simple on purpose — we want to see what you do 
with space. Phase 2 raises the ceiling — we want to see what 
you do with a real codebase and a real problem.

The challengers who perform best don't just complete the tasks.
They leave the repo better than they found it.
